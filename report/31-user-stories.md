## 3.1. User Stories

|Story ID|Título|Descripción|Criterios de Aceptación|Epic ID|
|:---|:---|:---|:---|:---|
|US01|Registro de administrador con validación de edificio|Como administrador, quiero registrarme en CodeNova asociando mi edificio, para habilitar el monitoreo de mis equipos desde el primer día.|Escenario (Éxito):Dado que el administrador completa los datos del edificio y su cuenta, Cuando presiona 'Crear cuenta', Entonces el sistema crea el edificio y envía un correo de confirmación. Escenario (Fracaso):Dado que el correo ingresado ya está registrado, Cuando intenta crear la cuenta, Entonces el sistema muestra 'Este correo ya tiene una cuenta asociada'.|EPCN01|
|US02|Inicio de sesión por rol|Como usuario registrado (administrador, residente o empresa de mantenimiento), quiero iniciar sesión con mi correo y contraseña, para acceder a las funciones de mi rol.|Escenario (Éxito):Dado que el usuario ingresa credenciales correctas, Cuando presiona 'Iniciar sesión', Entonces el sistema lo redirige al dashboard de su rol. Escenario (Fracaso):Dado que el usuario ingresa una contraseña incorrecta, Cuando presiona 'Iniciar sesión', Entonces el sistema muestra 'Correo o contraseña incorrectos'.|EPCN01|
|US03|Recuperación de contraseña|Como usuario registrado, quiero recuperar mi contraseña olvidada, para volver a acceder a mi cuenta.|Escenario (Éxito): Dado que el usuario ingresa su correo registrado, Cuando presiona 'Enviar enlace', Entonces el sistema envía un correo de recuperación válido por 24 horas. Escenario (Fracaso): Dado que el usuario usa un enlace de recuperación vencido, Cuando intenta acceder a él, Entonces el sistema muestra 'Este enlace ha expirado. Solicita uno nuevo'.|EPCN01|
|US04|Registro de residente vinculado a su unidad|Como residente, quiero registrarme indicando mi edificio y número de departamento, para reportar incidentes y hacer seguimiento a mis solicitudes.|Escenario (Éxito): Dado que el residente ingresa un código de edificio válido y un número de unidad existente, Cuando presiona 'Registrarme', Entonces el sistema crea la cuenta y notifica al administrador. Escenario (Fracaso): Dado que el residente ingresa un código de edificio inexistente, Cuando intenta registrarse, Entonces el sistema muestra 'Código de edificio no válido'.|EPCN01|
|US05|Registro de empresa de mantenimiento|Como empresa de mantenimiento, quiero registrarme y asociarme a uno o más edificios, para recibir alertas y gestionar mis visitas desde la plataforma.|Escenario (Éxito): Dado que la empresa completa el formulario de registro con su RUC y edificios asignados, Cuando presiona 'Registrar empresa', Entonces el sistema crea la cuenta y la vincula a los edificios indicados. Escenario (Fracaso): Dado que el RUC ingresado no tiene el formato correcto, Cuando intenta registrarse, Entonces el sistema muestra 'Ingresa un RUC válido de 11 dígitos'.|EPCN01|
|US06|Edición de datos de perfil|Como usuario registrado, quiero editar mis datos de perfil (nombre, teléfono, correo), para mantener actualizada mi información de contacto.|Escenario (Éxito): Dado que el usuario modifica un campo válido de su perfil, Cuando presiona 'Guardar cambios', Entonces el sistema actualiza la información y confirma el cambio. Escenario (Fracaso): Dado que el usuario ingresa un número de teléfono con formato inválido, Cuando intenta guardar, Entonces el sistema muestra 'Ingresa un número de teléfono válido'.|EPCN01|
|US07|Registro de un edificio y sus datos generales|Como administrador, quiero registrar los datos generales de mi edificio (dirección, número de unidades, distrito), para que la plataforma configure correctamente el monitoreo.|Escenario (Éxito): Dado que el administrador completa los datos del edificio, Cuando presiona 'Guardar edificio', Entonces el sistema lo registra y lo muestra en su panel. Escenario (Fracaso): Dado que el administrador deja el campo de dirección vacío, Cuando intenta guardar, Entonces el sistema muestra 'La dirección es obligatoria'.|EPCN02|
|US08|Registro de equipos críticos del edificio|Como administrador, quiero registrar los equipos críticos de mi edificio (bombas, tableros, ascensores, aires acondicionados), para que la plataforma pueda asociarles sensores y generar alertas.|Escenario (Éxito): Dado que el administrador completa el tipo y ubicación del equipo, Cuando presiona 'Guardar equipo', Entonces el sistema lo agrega a la lista de equipos del edificio con un código único. Escenario (Fracaso): Dado que el administrador no selecciona un tipo de equipo, Cuando intenta guardar, Entonces el sistema muestra 'Selecciona el tipo de equipo'.|EPCN02|
|US09|Edición o baja de un equipo registrado|Como administrador, quiero editar o dar de baja un equipo registrado, para mantener actualizado el inventario cuando se reemplaza o retira un equipo.|Escenario (Éxito): Dado que el administrador marca un equipo como 'dado de baja', Cuando confirma la acción, Entonces el sistema deja de generar alertas para ese equipo, conservando su historial. Escenario (Fracaso): Dado que el equipo tiene una visita de mantenimiento programada activa, Cuando el administrador intenta darlo de baja, Entonces el sistema muestra 'No puedes dar de baja un equipo con una visita programada activa'.|EPCN02|
|US10|Asociación de sensores a un equipo específico|Como administrador, quiero asociar uno o más sensores IoT a un equipo registrado, para que las lecturas se vinculen correctamente y generen alertas sobre ese equipo.|Escenario (Éxito): Dado que el administrador ingresa un identificador de sensor válido y no utilizado, Cuando confirma la asociación, Entonces el sensor queda vinculado al equipo. Escenario (Fracaso): Dado que el identificador de sensor ya está asociado a otro equipo, Cuando el administrador intenta asociarlo, Entonces el sistema muestra 'Este sensor ya está asociado a otro equipo'.|EPCN02|
|US11|Consulta del listado de equipos por edificio|Como administrador, quiero ver el listado completo de equipos registrados en mi edificio con su estado actual, para tener una visión general del parque de equipos.|Escenario (Éxito): Dado que el edificio tiene equipos registrados, Cuando el administrador accede a 'Mis equipos', Entonces el sistema muestra la lista con su tipo, ubicación y estado. Escenario (Fracaso): Dado que el edificio no tiene equipos registrados, Cuando el administrador accede a 'Mis equipos', Entonces el sistema muestra 'Aún no has registrado equipos en este edificio'.|EPCN02|
|US12|Recepción y registro de lecturas de sensores|Como sistema, quiero recibir y almacenar las lecturas de vibración, temperatura, humedad y consumo eléctrico enviadas por los sensores, para contar con el historial necesario para generar alertas.|Escenario (Éxito): Dado que un sensor envía una lectura dentro de rango físico válido, Cuando el sistema la recibe, Entonces la almacena asociada al equipo correspondiente con marca de tiempo. Escenario (Fracaso): Dado que un sensor envía un valor fuera de rango físico posible, Cuando el sistema la recibe, Entonces la descarta y la marca como lectura errónea.|EPCN03|
|US13|Detección de sensor desconectado|Como sistema, quiero detectar cuando un sensor deja de enviar lecturas durante un periodo prolongado, para notificar al administrador que el monitoreo de ese equipo está interrumpido.|Escenario (Éxito): Dado que un sensor no envía lecturas durante más de 24 horas, Cuando el sistema evalúa su estado, Entonces genera una notificación de 'sensor desconectado' al administrador. Escenario (Fracaso): Dado que el sensor retoma el envío de lecturas antes de las 24 horas, Cuando el sistema evalúa su estado, Entonces no genera ninguna notificación.|EPCN03|
|US14|Consulta del historial de lecturas de un equipo|Como administrador, quiero consultar el historial de lecturas de un equipo en un rango de fechas, para entender su comportamiento a lo largo del tiempo.|Escenario (Éxito): Dado que el equipo tiene lecturas registradas en el rango solicitado, Cuando el administrador aplica el filtro de fechas, Entonces el sistema muestra el gráfico de lecturas correspondiente. Escenario (Fracaso): Dado que no existen lecturas en el rango de fechas solicitado, Cuando el administrador aplica el filtro, Entonces el sistema muestra 'No hay lecturas registradas en este periodo'.|EPCN03|
|US15|Configuración de rangos esperados por tipo de equipo|Como sistema, quiero mantener rangos de referencia configurables por tipo de equipo (vibración, temperatura, amperaje), para poder comparar cada lectura contra un valor esperado.|Escenario (Éxito):Dado que un administrador de plataforma actualiza el rango esperado de un tipo de equipo, Cuando guarda el cambio, Entonces el sistema aplica el nuevo rango a las evaluaciones futuras. Escenario (Fracaso):Dado que el rango mínimo ingresado es mayor que el rango máximo, Cuando se intenta guardar, Entonces el sistema muestra 'El valor mínimo no puede ser mayor al máximo'. |EPCN03|
|US16|Visualización de gráfico de lecturas en tiempo real|Como administrador, quiero ver un gráfico en tiempo real de la última lectura de un equipo, para monitorear su comportamiento durante el día.|Escenario (Éxito): Dado que el equipo tiene un sensor activo, Cuando el administrador abre el detalle del equipo, Entonces el sistema muestra el gráfico actualizado con la última lectura recibida. Escenario (Fracaso): Dado que el equipo no tiene ningún sensor asociado, Cuando el administrador abre su detalle, Entonces el sistema muestra 'Este equipo no tiene sensores asociados'.|EPCN03|
|US17|Generación automática de alertas por severidad|Como sistema, quiero comparar cada lectura contra los rangos esperados del equipo y generar una alerta con nivel de severidad cuando se supere el umbral, para anticipar fallas antes de que ocurran.|Escenario (Éxito): Dado que una lectura de vibración supera el umbral crítico configurado, Cuando el sistema la evalúa, Entonces genera una alerta de severidad Crítica. Escenario (Fracaso): Dado que la lectura se mantiene dentro del rango esperado, Cuando el sistema la evalúa, Entonces no genera ninguna alerta.|EPCN04|
|US18|Actualización de una alerta activa|Como sistema, quiero actualizar una alerta ya activa cuando llegan nuevas lecturas relacionadas con la misma anomalía, para evitar duplicar alertas del mismo problema.|Escenario (Éxito): Dado que ya existe una alerta activa para un equipo, Cuando llega una nueva lectura que confirma el mismo problema, Entonces el sistema actualiza la severidad de la alerta existente en vez de crear una nueva. Escenario (Fracaso): Dado que la nueva lectura corresponde a una anomalía distinta, Cuando el sistema la evalúa, Entonces genera una alerta independiente.|EPCN04|
|US19|Visualización de alertas activas en el dashboard|Como administrador, quiero ver en mi dashboard las alertas activas de mi edificio ordenadas por severidad, para decidir qué equipo requiere atención primero.|Escenario (Éxito): Dado que el edificio tiene alertas activas, Cuando el administrador ingresa al dashboard, Entonces el sistema muestra la lista ordenada de mayor a menor severidad. Escenario (Fracaso): Dado que no hay alertas activas, Cuando el administrador ingresa al dashboard, Entonces el sistema muestra 'Sin alertas activas' y el estado general del edificio.|EPCN04|
|US20|Cambio de estado de una alerta|Como administrador, quiero marcar una alerta como 'en gestión' o 'resuelta', para reflejar el avance real de la atención del problema.|Escenario (Éxito): Dado que el administrador selecciona una alerta activa, Cuando cambia su estado a 'en gestión', Entonces el sistema actualiza el estado y lo refleja en el dashboard. Escenario (Fracaso): Dado que la alerta ya fue marcada como 'resuelta', Cuando el administrador intenta cambiar su estado nuevamente, Entonces el sistema muestra 'Esta alerta ya fue cerrada'.|EPCN04|
|US21|Notificación de alerta priorizada a la empresa de mantenimiento|Como empresa de mantenimiento, quiero recibir una notificación cuando se genera una alerta de severidad Alta o Crítica en un edificio que atiendo, para priorizar la visita.|Escenario (Éxito): Dado que se genera una alerta Crítica en un edificio con empresa de mantenimiento asignada, Cuando el sistema la procesa, Entonces envía la notificación correspondiente con el detalle del equipo. Escenario (Fracaso): Dado que el edificio no tiene empresa de mantenimiento asignada, Cuando se genera la alerta, Entonces el sistema solo notifica al administrador.|EPCN04|
|US22|Configuración de umbrales de severidad por edificio|Como administrador, quiero ajustar la sensibilidad de las alertas de mi edificio dentro de rangos permitidos, para adaptar el sistema a las particularidades de mis equipos.|Escenario (Éxito): Dado que el administrador ajusta un umbral dentro del rango permitido por el sistema, Cuando guarda el cambio, Entonces el sistema aplica el nuevo umbral a las evaluaciones futuras. Escenario (Fracaso): Dado que el administrador intenta ajustar un umbral fuera del rango permitido, Cuando intenta guardar, Entonces el sistema muestra 'El valor ingresado está fuera del rango permitido'.|EPCN04|
|US23|Reporte de incidente por parte del residente|Como residente, quiero reportar un incidente indicando el tipo de problema y una breve descripción, para que la administración tome conocimiento y lo gestione.|Escenario (Éxito): Dado que el residente completa el formulario con categoría y descripción, Cuando presiona 'Enviar', Entonces el sistema confirma la recepción y notifica al administrador. Escenario (Fracaso): Dado que el residente no selecciona una categoría, Cuando intenta enviar el reporte, Entonces el sistema muestra 'Selecciona un tipo de incidente'.|EPCN05|
|US24|Adjuntar foto a un reporte de incidente|Como residente, quiero adjuntar una foto a mi reporte de incidente, para que el administrador entienda mejor el problema.|Escenario (Éxito): Dado que el residente adjunta una imagen en formato válido y de tamaño permitido, Cuando envía el reporte, Entonces el sistema la almacena junto con el incidente. Escenario (Fracaso): Dado que el residente intenta adjuntar un archivo que excede el tamaño permitido, Cuando intenta enviarlo, Entonces el sistema muestra 'El archivo supera el tamaño máximo permitido (5MB)'.|EPCN05|
|US25|Seguimiento del estado de un incidente reportado|Como residente, quiero ver el estado de mi incidente reportado (recibido, en gestión, resuelto), para saber si ya está siendo atendido sin llamar a la administración.|Escenario (Éxito): Dado que el administrador marca un incidente como 'en gestión', Cuando el sistema procesa el cambio, Entonces notifica al residente y actualiza el estado visible. Escenario (Fracaso): Dado que el residente consulta un incidente que no le pertenece, Cuando intenta acceder a su detalle, Entonces el sistema muestra 'No tienes acceso a esta solicitud'.|EPCN05|
|US26|Asignación de un incidente a una visita de mantenimiento|Como administrador, quiero asociar un incidente reportado a una visita de mantenimiento programada o de emergencia, para centralizar la gestión y evitar duplicar solicitudes.|Escenario (Éxito): Dado que el administrador selecciona un incidente y una visita programada, Cuando confirma la asociación, Entonces el estado del incidente cambia a 'en gestión' y se notifica al residente. Escenario (Fracaso): Dado que el incidente ya está vinculado a otra visita, Cuando el administrador intenta asignarlo nuevamente, Entonces el sistema muestra 'Este incidente ya está asignado a una visita'.|EPCN05|
|US27|Calificación del incidente resuelto|Como residente, quiero calificar la atención recibida una vez que mi incidente se marca como resuelto, para dar retroalimentación sobre el servicio de mantenimiento.|Escenario (Éxito): Dado que el incidente fue marcado como 'resuelto', Cuando el residente selecciona una calificación de 1 a 5 estrellas, Entonces el sistema la registra y la asocia a la intervención. Escenario (Fracaso): Dado que el incidente aún no ha sido marcado como 'resuelto', Cuando el residente intenta calificarlo, Entonces el sistema muestra 'Podrás calificar esta solicitud una vez resuelta'.|EPCN05|
|US28|Programación de visita de mantenimiento preventivo|Como administrador, quiero programar una visita de mantenimiento preventivo para un equipo con alerta activa, para intervenir antes de que la falla se agrave.|Escenario (Éxito): Dado que el administrador elige equipo, empresa y fecha propuesta, Cuando confirma la programación, Entonces el sistema crea la visita con estado 'programada' y notifica a la empresa. Escenario (Fracaso): Dado que la empresa de mantenimiento no tiene disponibilidad en la fecha propuesta, Cuando el administrador confirma, Entonces el sistema muestra 'La empresa no tiene disponibilidad en esa fecha, elige otra'.|EPCN06|
|US29|Confirmación o reprogramación de una visita|Como empresa de mantenimiento, quiero confirmar o proponer una nueva fecha para una visita programada, para ajustarla a mi disponibilidad real.|Escenario (Éxito): Dado que la empresa recibe una visita propuesta, Cuando confirma la fecha, Entonces el sistema marca la visita como 'confirmada' y notifica al administrador. Escenario (Fracaso): Dado que la empresa propone una nueva fecha fuera del plazo máximo permitido para una alerta Crítica, Cuando intenta guardar, Entonces el sistema muestra 'Esta alerta requiere atención dentro de las próximas 48 horas'.|EPCN06|
|US30|Consulta de datos técnicos previos antes de la visita|Como técnico de mantenimiento, quiero consultar las últimas lecturas y el historial del equipo antes de asistir a una visita, para reducir mi tiempo de diagnóstico en campo.|Escenario (Éxito): Dado que el técnico abre una visita asignada, Cuando accede a 'Detalle del equipo', Entonces el sistema muestra las últimas lecturas y el historial de intervenciones. Escenario (Fracaso): Dado que el equipo no tiene intervenciones previas registradas, Cuando el técnico consulta el detalle, Entonces el sistema muestra 'Sin intervenciones previas registradas'.|EPCN06|
